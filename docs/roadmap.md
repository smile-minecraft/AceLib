## 怎麼更新這份文件

這份文件是任務清單。`[ ]` 是還沒完成，`[x]` 是完成。

完成一個項目時，只把那一行的 `[ ]` 改成 `[x]`，其他都不動：

- 項目的文字不改寫，也不在後面加註結果、驗證方式、日期或測試數量。
- 段落標題不改名，項目不在段落之間搬動。
- 修了什麼、行為變成怎樣，寫進 [CHANGELOG.md](../CHANGELOG.md) 和對應的模組頁。
- 實機確認有自己的清單。程式修好但還沒上實機時，勾修正項目，不勾實機確認。

修正項目可以勾選的條件是：程式已修正，有先失敗、後通過的回歸測試，全部既有測試通過。

新增、刪除、改寫項目，或調整順序，屬於範圍變更，要先經維護者同意。提案時說明：

- 哪個下游 plugin 已經自己維護這段邏輯，位置在哪裡。沒有的話也請寫明。
- AceLib 負責的範圍，和留給下游判斷的部分。
- 驗收情境，包含 Paper 和 Folia 的差異。

版本發布後，整個版本的段落從這裡移除，內容以 CHANGELOG 為準。

## 規劃原則

AceLib 要讓下游 plugin 少寫重複的程式碼，也更容易寫對。規劃時依下列幾點判斷：

- 下游佐證決定先後。下游已經自己維護同類邏輯的項目先做，兩個下游都重複實作的排最前面。目前對照的下游是 ChunkLand 與 Ace-Economy。還沒有下游在用的項目排在後段，各項說明會寫明。
- AceLib 管流程和安全邊界。誰可以做什麼、價格、權限、操作對象，留給下游 plugin 判斷。
- 缺陷先修。新功能依賴的部分有已知缺陷時，先修缺陷。
- 公開 API 可以在版本之間變更。破壞性變更要先記在這份路線圖並標明版本，發布時寫進 CHANGELOG；公開型別有增減或簽章改變時，更新 [API surface](reference/api-surface.md) 分類和簽章基線。
- Paper 和 Folia 都要驗證。行為不同的功能要有兩組測試。牽涉時序和執行緒的項目還要實機驗證，MockBukkit 測不出真實 Folia 的行為。
- 每個新模組要有模組頁，consumer 範例裡要有能編譯的用法。

## AceLib 1.4.0 新功能

原本分散在後續版本的規劃都併進這一版，共十一項，依相依關係分成四個階段。階段是動工順序。

前兩個階段的項目，下游都已經有自己維護的程式碼。第三、第四階段有幾項目前沒有下游在用，是維護者決定排入的，各項會寫明。

每一項底下的清單是交付內容，做完一條勾一條。

### 第一階段 測試與排程

#### 測試套件

ChunkLand 和 Ace-Economy 各寫了一份 GUI 假實作，另外還有排程、表單、基岩服務的 stub。兩邊的程式碼重複，也容易和 AceLib 的實際行為對不上。

測試套件提供這些假實作，給下游寫單元測試用。真實伺服器上的驗收由 Docker 管理的測試環境負責，不在測試套件的範圍。

- [x] 確認 Gradle 的 test fixtures 產出的 jar 可以透過 JitPack 發布，下游能在測試時引用。行不通就回到[待決事項](#待決事項)重新決定發布方式。
- [x] 測試 jar 也附在 GitHub Release 上，發布 workflow 跟著調整。ChunkLand 是從 Release 下載 AceLib 的。
- [x] 文件寫明下游的引用方式：在 AceLib 的座標後面加上 `test-fixtures` 後綴。Gradle 的 `testFixtures(...)` 寫法在 JitPack 上解析不到。
- [x] 可控制的時鐘、排程器、實體退休事件。
- [x] GUI 與表單的標準假實作，能模擬過時回應、重複回應、關閉失敗。
- [x] Provider 缺席、停用、重新取得的測試輔助。
- [x] 一套服務契約測試，真實作和假實作都要通過。

#### 任務完成語意與作用域

現在的排程結果只代表已經排程，動作有沒有做完無從得知。GUI 用自己的結果狀態處理這件事；下游各自拼出「背景計算，再回玩家執行緒」的流程。

要先有 AceLib 1.3.1 的 Folia 任務取消和退休回呼。

- [x] 排程結果能分辨「已接受排程」和「動作已完成」，可以等待，也可以串接。
- [x] 任務群組以玩家或實體為作用域。玩家退服、實體退休、plugin 停用時，群組裡的任務自動取消並通知呼叫端。
- [x] 讀取、背景計算、回到玩家所在執行緒回覆，可以串成一條流程。
- [x] 驗收情境：玩家退服、跨區移動、排程被拒絕。

#### 事件處理完成後的操作

取消移動事件之後立刻傳送，傳送就算回報成功，位置還是可能被事件處理還原。現有的傳送 API 收到請求就立刻傳送，會遇到同一個問題。ChunkLand 的做法是自己組合下一 tick、玩家執行緒、非同步傳送和失敗回報。

- [x] 延後傳送：排到之後的 tick，在玩家所在的執行緒傳送，完成時確認玩家真的到了目的地，沒到就回報失敗。
- [x] 同樣的延後方式可以用在傳送以外的操作。
- [x] 驗收情境：傳送回報成功卻被還原。
- [x] Paper 實機驗證。
- [x] Folia 實機驗證。

### 第二階段 設定與訊息

#### 設定的啟動、快照與型別綁定

ChunkLand 自己寫了設定啟動解析，Ace-Economy 自己寫了設定轉接和嚴格驗證。現有的 `ConfigManager` 有三個缺口：檔案不存在就建立預設檔，分不出首次安裝和用過之後被刪；交給下游的設定物件可以被改動；schema 只檢查必填欄位在不在。

設定損壞時要禁止哪些操作，由下游 plugin 決定。

- [x] 啟動結果分四類：首次安裝、有效設定、損壞設定、使用後缺檔。
- [x] 保留最後一次驗證成功的設定副本。
- [x] 設定損壞時不覆寫操作者的原檔，呼叫端可以指定保守的後備設定。
- [x] 整份設定先驗證，通過後一次發布不可變的快照。同一輪操作固定用同一個快照。
- [x] 設定對應到 record 或一般類別。型別、數值範圍、列舉值在載入時驗證，錯誤訊息帶出完整路徑。
- [x] 監看檔案變更並自動重載。新內容驗證失敗時保留舊快照，記錄原因。
- [x] 寫回時保留註解，缺的 key 補上預設值和說明。

#### 插件作用域的訊息與在地化

ChunkLand 有自己的訊息管線，Ace-Economy 有設定與語系轉接。現有的 `LangManager` 只讀磁碟上的語系檔，plugin 內建的資源讀不到。

玩家語系偏好存在哪裡不做規定，下游可以用自己的資料庫。

- [x] 以 plugin 為作用域的工廠，統一建立和清理訊息服務。
- [x] 玩家語系解析器可以替換。
- [x] 磁碟上的自訂文案優先，缺的 key 才讀內建資源。
- [x] 升級時只補新 key，伺服器管理員改過的文案不動。
- [x] 聊天、ActionBar、GUI、表單共用同一份渲染結果。
- [x] 顯示標籤和程式識別字分開。
- [x] 缺 key 和渲染失敗都能診斷。

### 第三階段 介面與指令

#### 介面流程與元件

兩個下游都在現有的 GUI 與表單服務上面，各自維護導航狀態、點擊監聽和表單 session。GUI 服務沒有點擊回呼，下游得自己監聽 inventory 事件。ChunkLand 還拿「受保護欄位被拒絕」的錯誤碼當按鈕訊號。

授權、價格、操作對象仍由下游判斷。佈局引擎和資料綁定不做。

動工前要完成任務完成語意與作用域和 AceLib 1.3.1 的 reload 修正。GUI 服務的作用域依[待決事項](#待決事項)第一項的決定。

流程：

- [x] 每個 plugin 取得自己的 GUI 作用域 handle，只能操作自己開的 GUI；公開介面上關閉整個服務的方法移除。
- [x] 玩家開著別的 plugin 的 GUI 時，新的 GUI 取代舊的，並通知原本的 plugin。
- [x] `open`、`push`、`replace`、`back`、`close` 五個導航操作。
- [x] 同一份流程對應 Java GUI 和基岩表單兩種呈現。
- [x] 非同步載入、錯誤畫面、返回狀態。
- [x] 共用的一次性確認票券。
- [x] 回應過時、玩家退服、plugin 停用時自動失效。
- [x] 送出時重新驗證的回呼入口。

元件：

- [x] 按鈕與點擊回呼、分頁、確認視窗。
- [x] 輸入提示，支援聊天輸入和鐵砧。
- [x] 欄位預設全部擋下，只開放指定的欄位。按鈕內建點擊冷卻。

#### 型別化的指令框架

現有的指令模型沒有給下游的正式組裝入口，[指令模型](modules/command.md)頁要下游先用 Paper 自己的指令 API。Ace-Economy 仍然大量引用這個模組，但還沒有提出具體痛點，所以這一項排在介面之後。

宣告方式先做 builder 風格。底層改用 Paper 的 Brigadier 指令註冊方式，現有的 `SubCommandSpec` 留作相容層。

基岩版玩家透過 Geyser 連線時，補全只認得指令結構裡固定的選項，伺服器即時算出來的建議送不到基岩版。這一項要讓基岩版玩家也有堪用的補全。

- [x] 底層改用 Brigadier 註冊，指令不必再寫進 `plugin.yml`。
- [x] AceLib 自己的 reload 配合 Brigadier 的註冊時機調整。
- [x] 給下游的正式組裝入口。
- [x] 引數型別：玩家、離線玩家、整數與小數範圍、時間長度、世界、列舉、材質。
- [x] 依引數型別自動補全，依權限過濾說明，錯誤訊息走在地化。
- [x] 固定的選項以基岩版看得到的方式註冊，讓 Geyser 玩家也有補全。
- [x] 實測各引數型別在基岩版的補全，結果記在模組頁。
- [x] 沿用現有的冷卻。
- [x] Paper 實機驗證：指令在哪個執行緒執行、輸入錯誤的提示、補全。
- [x] Folia 實機驗證：指令在哪個執行緒執行、輸入錯誤的提示、補全。

### 第四階段 資料與整合

#### 儲存層與玩家資料

目前沒有下游使用玩家資料和資料儲存模組，這一項是維護者決定排入的。玩家資料服務維持在 AceLib 啟動時就啟動；現在的做法是玩家離線時重寫整個檔案。

- [x] 每位玩家獨立儲存。預設 SQLite，可以換成 MySQL。
- [x] 資料模型以 record 宣告，編解碼由 AceLib 處理。
- [x] 登入前預先載入，資料就緒時發出事件。
- [x] 定期保存。伺服器異常結束時，最多遺失一個保存週期的變更。
- [x] 可以讀取離線玩家的資料。
- [x] JDBC store 保存時只寫有變動的資料。

#### 外部整合門面

外部整合模組現在只回報 Vault、LuckPerms、PlaceholderAPI、Floodgate 在不在。ChunkLand 自己維護 Vault 的探測、轉接和不可用時的替代實作；權限、佔位符、區域保護三類目前沒有下游提出需求。

AceLib 只包裝外部 plugin 的服務。

- [x] 經濟：查餘額、扣款、入帳。
- [x] 權限：查群組與情境。
- [x] 佔位符：註冊自己的佔位符。
- [x] 區域保護：查玩家能不能在某個位置建造。
- [x] 外部 plugin 不在時，回報明確的不可用結果。

#### 每位玩家的顯示工具

在 Folia 上，每位玩家的顯示更新要回到該玩家所在的執行緒，這一項把排程和清理包起來。目前沒有下游提出需求。

- [x] 計分板。
- [x] BossBar。
- [x] 全息字。

#### 生命週期宿主

AceLib 自己的 reload 已經有提交與回滾的流程，這一項把它抽出來給下游用。

它排在最後。前面各項的服務都要由它接線，那些服務穩定之前做不了。目前也沒有下游提出需求。

- [x] 下游 plugin 宣告自己的模組和相依關係。
- [x] 啟用順序、停用順序由 AceLib 安排。
- [x] reload 和失敗回滾由 AceLib 安排。

### 發布前要確認的事

- [x] 新增的公開型別已分類，簽章基線已更新，既有簽章沒有變動。
- [x] 牽涉時序和執行緒的項目完成 Paper 與 Folia 實機驗證。

## AceLib 1.5.0 修補與指令引數

這一版處理 Ace-Economy 對 AceLib 1.4.0 提出的回報。回報共 26 項，逐項對過原始碼後，確認要動的項目列在下面，依風險分成五個階段。階段是動工順序。

Ace-Economy 為了這些缺口自己維護的程式碼在：`commands/v2/**` 與 `V2CommandRegistry`（指令）、`infrastructure/acelib/ConfigLangAdapter.java` 與 `V2FixedSettings.java`（設定與語系）、`infrastructure/persistence/**` 與 `application/EconomyService.java`（資料）、`infrastructure/integration/discord/**`（外部頻道訊息）。ChunkLand 沒有提出同類需求。

幣別、金額精度、負債政策、誰可以動誰的錢，仍由 Ace-Economy 判斷。AceLib 只提供通用的引數型別、設定繫結、寫入原語和介面版面。

破壞性變更有三項，各自在所屬項目標明：純文字路徑開始跳脫變數值、指令錯誤分類改名、`ConfigSnapshot.getInt` 拒絕小數與溢位。後兩項依[待決事項](#待決事項)第九項的決定。

### 第一階段 文件與測試

不改行為。文件和實際行為對不上的地方先修，免得下游照著文件設計後卡住。

- [ ] `Arguments` 的註解寫八種引數型別，公開工廠方法有九個，改成九個。
- [ ] 指令模組頁寫明一個子指令名稱只能有一組引數，重複名稱在註冊時被拒絕。
- [ ] `ACELIB-CMD-008` 在錯誤碼表和 `CommandErrorKind` 的說明改成 handler 執行失敗。handler 是在平台派送的執行緒同步執行的。
- [ ] `RenderedMessage.text()` 的說明改掉「純文字」的說法，寫明它保留 MiniMessage 標記。
- [ ] 事件模組頁寫明沒有「操作提交成功後」的回呼，要由下游自行組合。
- [ ] 排程模組頁寫明沒有重試和延遲策略，要由呼叫端負責。
- [ ] 生命週期模組頁寫明宿主只有一個，由 AceLib 持有，下游不能自建。
- [ ] 生命週期模組頁寫明 `close()` 擲出 `Error` 時宿主還會做什麼，並補上對應的測試。

### 第二階段 行為缺陷

這四項是現有功能的錯誤，後面的新介面有幾項建立在它們上面，所以先修。

- [x] 設定繫結的 double 欄位拒絕 `NaN` 和無限大，錯誤訊息帶完整路徑和允許範圍。現在 `NaN` 有設範圍也會通過。
- [x] 以指定語系渲染訊息時，前綴也取同一個語系。現在正文用指定語系，前綴用全域目前語系。
- [x] 以 `DataStore` 包裝的逐玩家儲存，儲存失敗時回復已修改的記憶體資料。
- [x] 純文字路徑和富文字路徑一樣跳脫變數值裡的 MiniMessage 標記。破壞性變更：玩家名稱或自訂文字帶 `<...>` 時，純文字輸出會和 AceLib 1.4.0 不同。
- [x] 驗收情境：設定檔寫 `.nan` 和 `.inf`；以非全域語系渲染帶前綴的訊息；儲存失敗後再讀同一個欄位；變數值帶 `<red>`。

### 第三階段 型別化指令的引數

Ace-Economy 的 16 個經濟子指令裡有 12 個引數數量可變，目前沒辦法換到型別化路徑。自訂引數型別是其他幾項的前提，排最前面，其餘依下列順序動工。

動態選項做成開放式引數節點，不做成固定選項分支。固定選項在註冊時就編進平台的指令樹，平台沒有取消單一註冊的方法，執行期無法增刪。

- [x] 下游可以實作自己的引數型別。`ArgumentTypeFactory` 公開，另外提供只需要解析和補全函式就能建立引數的工廠方法。
- [x] consumer 範例裡有一個從外部套件實作的引數型別，能編譯，補全會列出它的選項，非法值的錯誤訊息走在地化。
- [x] 以 `BigDecimal` 解析的數值引數，可以指定範圍和小數位上限，解析失敗回 `ACELIB-CMD-015`。
- [x] 引數可以省略並帶預設值，最後一個引數可以重複。handler 拿到的仍是各自型別的值，不是字串清單。
- [x] 選項由供應函式提供的引數型別，補全和驗證每次都取最新的集合。
- [x] 固定選項輸入錯誤時，錯誤訊息走 `CommandMessages`。其他引數型別的範圍依[待決事項](#待決事項)第八項的決定。
- [x] 本版新增的引數型別，以及省略與重複引數的數量錯誤，錯誤訊息都走 `CommandMessages`。
- [x] 指令模組頁列出哪些既有引數型別的錯誤訊息由平台產生、不能客製。
- [x] 子指令別名。別名和其他子指令名稱衝突時，在註冊時拒絕。
- [x] `CommandErrorKind.ASYNC_EXECUTION_FAILED` 改名為 `EXECUTION_FAILED`，錯誤碼 `ACELIB-CMD-008` 不變。破壞性變更。
- [x] 驗收情境：省略玩家引數時作用在自己；重複引數給零個、一個、多個；小數位超過上限；選項集合在執行期增刪後的補全和驗證；以別名執行子指令。
- [x] Paper 實機驗證：省略與重複引數的補全和錯誤提示、固定選項輸入錯誤的訊息。
- [x] Folia 實機驗證：省略與重複引數的補全和錯誤提示、固定選項輸入錯誤的訊息。

### 第四階段 訊息、設定與資料的新增介面

這些項目 Ace-Economy 都有自己的繞法，補上之後可以拿掉轉接層。

通用的寫入原語只管「讀、檢查、套用」這一步的原子性。交易紀錄、防止重複扣款、外部副作用的恢復仍然不做。

訊息：

- [x] 渲染結果能分辨語系尚未載入、缺 key、渲染失敗。缺 key 的診斷帶完整 key 和可用的語系。
- [x] 發送訊息的方法回傳結果，至少包含是否套用了基岩降級。
- [x] 基岩降級可以選擇攤平成純文字。
- [x] 給 console 和外部頻道用的純文字輸出：標記全部去除，可以選擇要不要帶前綴。
- [x] 驗收情境：含 `<red>` 和 `<gradient>` 的模板在純文字輸出只剩可讀文字；基岩玩家收到降級訊息時呼叫端拿得到降級旗標。

設定：

- [x] `ConfigSnapshot` 有相等語意和遞增的世代號，下游能判斷 reload 之後內容有沒有變。
- [x] `ConfigSnapshot` 補上 `getLong` 和 `getDouble`。
- [x] `ConfigSnapshot.getInt` 遇到小數和溢位時報錯。破壞性變更。
- [x] 設定繫結支援 `Map<String, T>`、`Set<T>` 和物件清單，清單元素依宣告的型別驗證。
- [x] 跨欄位驗證的入口。整份設定通過後才發布新快照，失敗時保留舊快照。
- [x] 使用後缺檔時，下游可以在還原最後成功副本之前攔截，選擇直接失敗。
- [x] 驗收情境：`Map` 裡某一筆缺欄位時，錯誤訊息指出那一筆的完整路徑；跨欄位規則失敗時快照不換。

資料與診斷：

- [x] 逐玩家儲存提供以欄位 `revision` 為條件的寫入，`revision` 不符時不寫並回報。
- [x] 逐玩家儲存提供「讀、檢查、套用」的原子操作，檢查不過或儲存失敗時不留下部分修改。
- [x] 讀取離線玩家資料的非同步入口。
- [ ] `SafeScheduler` 可以清除錯誤紀錄，容量可以設定。
- [ ] 錯誤節流表清掉長時間沒有再出現的錯誤碼。
- [ ] 驗收情境：兩個寫入以同一個 `revision` 競爭時只有一個成功；玩家在原子操作進行中退服。

### 第五階段 介面版面與基岩表單驗證

按鈕的欄位現在寫在 `GuiView`，物品卻由下游的 renderer 另外放，同一個欄位編號要寫兩次，寫錯時畫面和可點的位置會對不上。Ace-Economy 的交易明細和排行榜在 `bootstrap/CompositionRoot.java` 自己做了分頁按鈕和物品渲染。ChunkLand 也自己維護 GUI 程式，排法是否相近還沒比對。

AceLib 負責把下游給的物品放到對的欄位，以及分頁清單的翻頁和狀態畫面。物品的名稱、說明文字和在地化文案由下游決定。依內容自動決定大小和位置的排版不做，資料變動後自動重畫的綁定也不做。這個範圍依[待決事項](#待決事項)第十項的決定。

基岩表單的相容矩陣目前只有 Simple 表單的紀錄，Modal 和 Custom 表單沒有人在基岩客戶端上看過。

這個階段和前四個階段互不相依。

版面：

- [ ] 比對 ChunkLand 與 Ace-Economy 現有的 GUI 排法，確認下面三項兩邊都用得上。用不上的項目回到[待決事項](#待決事項)重新決定。
- [ ] 字元遮罩：用幾行字串描述箱子，把符號換算成欄位清單。行數、每行長度和箱子大小不合時，在建立時拒絕。
- [ ] 按鈕宣告時可以一併給物品，由 AceLib 在玩家所在的執行緒放進對應欄位。
- [ ] 分頁清單元件：上一頁、下一頁、頁碼，以及空資料、載入中、錯誤三種畫面，建立在 `GuiPage` 和字元遮罩上。
- [ ] 按鈕帶有標籤時，共用流程的步驟可以由同一份宣告產生基岩表單。
- [ ] 驗收情境：翻到最後一頁再按下一頁；資料在翻頁之間變少；切換畫面後舊畫面的翻頁按鈕失效；玩家在載入中退服。
- [ ] Paper 實機驗證：物品位置和可點的欄位一致、翻頁。
- [ ] Folia 實機驗證：物品位置和可點的欄位一致、翻頁。
- [ ] 真人基岩客戶端驗證：箱子畫面經 Geyser 轉換後的物品位置和翻頁。

基岩表單驗證：

- [ ] 表單探針加入 Modal 表單的案例：兩個按鈕各自的回傳索引、直接關閉。
- [ ] 表單探針加入 Custom 表單的案例：input、dropdown、slider、stepSlider、toggle 的預設值、回傳值和元件順序。
- [ ] 以真人基岩客戶端觀察上面兩組案例，結果記進[表單相容矩陣](reference/bedrock-form-compatibility-matrix.md)。沒有觀察到的環境標為未驗證。

## 候選功能

還沒排入版本的項目：

- 事件優先級，以及忽略已取消事件的選項。目前固定為一般優先級。
- 以註解宣告指令。等 builder 風格的指令框架穩定後再評估。

## 不在範圍內

- 自訂物品的行為註冊。物品模組維持現有的識別、序列化和遷移。
- 自製經濟系統或權限系統。
- 下游 plugin 的領域規則，例如領地授權、價格、交易條件。
- 跨伺服器的資料同步和分散式訊息系統。
- 網頁後台和自動更新。
- 通用的物件關聯對應。
- GUI 的自動排版和資料綁定。
- 持久操作紀錄和外部副作用的恢復框架。防止重複扣款是經濟提供者的責任。

## 待決事項

決定之後勾選，並在該項底下加一行「決定：」寫結論。這是唯一可以在項目底下加文字的地方。

1. [x] GUI 服務的作用域。GUI 服務目前由所有 plugin 共用，每位玩家同時只能有一個 session，關閉服務的方法也在公開介面上。介面流程要建立在共用服務上，還是讓每個 plugin 取得自己的作用域實例？建議流程以 plugin 為作用域取得，底層的共用服務留著維持相容。

   決定：每個 plugin 取得自己的作用域 handle，只能操作自己開的 GUI；底層共用同一份 session 登記。公開介面上關閉整個服務的方法在 AceLib 1.4.0 移除。玩家開著別的 plugin 的 GUI 時，新的 GUI 取代舊的，原本的 plugin 會收到被取代的通知。

2. [x] 階段之間要不要發布預覽版。全部一起發布，下游要等到最後才用得到第一階段的成果。文件檢查已經有預覽版的路徑。

   決定：全部項目一起發布，階段之間不發布預覽版。

3. [x] 測試套件的發布方式：多模組結構、artifact 座標、JitPack 設定。

   決定：範圍縮小為假實作和契約測試，故障注入、實機驗證範例、專案範本不做。用 Gradle 的 test fixtures 發布，AceLib 維持單一模組；動工時先確認 JitPack 可行。

4. [x] 新 API 的穩定性標示。新模組第一版就列為 Supported，還是先用較寬鬆的分類發布一個版本？

   決定：新 API 不另外標示穩定性。版本之間可以有破壞性變更，變更要先記在這份路線圖，發布時寫進 CHANGELOG。

5. [x] 現有的傳送 API 為什麼沒被採用。下游的傳送流程沒有用世界模組，要先了解原因，才能決定事件處理完成後的操作長什麼樣子。

   決定：原因已查明。現有的傳送 API 收到請求就立刻傳送，沒有延後。在被取消的移動事件裡呼叫，平台會把玩家放回原位，API 仍回報成功，所以 ChunkLand 自己排到之後的 tick 再傳送。

6. [x] 持久操作紀錄的做法。一種是做成通用框架；另一種是讓 AceLib 的經濟門面在偵測到支援的提供者時傳遞操作識別碼，由提供者端去重。

   決定：不做。防止重複扣款是經濟提供者的責任，持久操作紀錄移到不在範圍內。

7. [x] 玩家資料服務的啟動時機。改成有下游註冊才啟動是行為變更，要先確認有沒有未列入對照的使用者。

   決定：維持現狀，AceLib 啟動時就啟動玩家資料服務。

8. [x] 引數輸入錯誤的訊息要客製到哪裡。固定選項可以加一個後備節點把錯誤導回 AceLib 的訊息。數值超出範圍、玩家選擇器這類由客戶端驗證的引數，要客製就得改用字串節點，Java 版客戶端會失去輸入時的即時驗證。建議只做固定選項，其餘在模組頁列為不可客製。

   決定：固定選項，加上本版新增的引數型別（自訂、`BigDecimal`、動態選項）與省略、重複引數，錯誤訊息都走 `CommandMessages`。既有的整數、小數、玩家、世界、時間引數維持現況，在模組頁列為不可客製。

9. [x] AceLib 1.5.0 要不要收兩項破壞性變更：`CommandErrorKind.ASYNC_EXECUTION_FAILED` 改名，以及 `ConfigSnapshot.getInt` 拒絕小數與溢位。建議都收。

   決定：兩項都收進 AceLib 1.5.0。

10. [x] 分頁清單元件（上一頁、下一頁、頁碼、空狀態）算不算[不在範圍內](#不在範圍內)的佈局引擎。Ace-Economy 的交易明細和排行榜自己做了分頁按鈕。決定之前不排入版本。

   決定：不算。字元遮罩、按鈕帶物品、分頁清單元件排入 AceLib 1.5.0。不在範圍內的項目改為自動排版和資料綁定。

11. [x] 基岩表單相容矩陣要不要擴到 Modal 和 Custom 表單。需要真人基岩客戶端實測，目前只有 Simple 表單有紀錄。決定之前不排入版本。

   決定：排入 AceLib 1.5.0，和介面版面同一個階段。
